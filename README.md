# uptime

[![probe](https://github.com/jamessuuu/uptime/actions/workflows/probe.yml/badge.svg)](https://github.com/jamessuuu/uptime/actions/workflows/probe.yml)
![sites up](https://img.shields.io/badge/dynamic/json?url=https%3A%2F%2Fraw.githubusercontent.com%2Fjamessuuu%2Fuptime%2Fmain%2Fstate%2Flatest.json&query=%24.summary.label&label=sites&color=informational)

External uptime probe for every live site I run. Born from a 90-minute outage of
[joinklik.app](https://joinklik.app) on 2026-09-26 that nobody noticed, because nothing
outside my own machine was looking.

**Status page:** https://jamessuuu.github.io/uptime/
**Incidents:** [issues labelled `uptime`](https://github.com/jamessuuu/uptime/issues?q=label%3Auptime)

## How it works

- `sites.json` is the single source. One line per site: slug, URL, and what a healthy
  response looks like (status, a string only the real page contains, a latency ceiling).
- `probe.mjs` (Node 22, zero dependencies) fetches every site concurrently with a 10 s
  timeout. Anything that fails is fetched once more 30 s later; only a second failure
  counts. It checks the status code, that the body contains the expected string, and
  that the body does not contain a Vercel login wall or a Cloudflare error page. A
  page that is up but slower than `maxMs` is recorded as `slow`, not down.
- GitHub Actions runs it every 15 minutes (`.github/workflows/probe.yml`). A run takes
  well under two minutes.
- Results go to `state/latest.json` and one line per recorded run in
  `state/history.ndjson`. The bot commits only when a site's state changed, or every
  6 hours as a heartbeat, so the history is in git and the repo is not spammed.
- One GitHub issue per down site, titled `DOWN: <slug>`, with the evidence (status,
  latency, first bytes, run link). It gets a comment if the failure reason changes and
  is closed with the recovery time when the site comes back. If the entry is removed
  from `sites.json`, the issue closes too.
- Optional phone push: add a repository secret `NTFY_TOPIC` (and `NTFY_SERVER` or
  `NTFY_TOKEN` if you self-host) and every open/close also posts to ntfy. Nothing is
  sent unless the secret exists.
- `docs/index.html` is the status page on GitHub Pages: current state plus 30-day bars
  per site drawn from `history.ndjson`, no libraries.

## Add a site

Add one line to the `sites` array in `sites.json`:

```json
{ "slug": "my-site", "url": "https://example.com", "expect": { "contains": "a string only the real page has" } }
```

`status` defaults to 200 and `maxMs` to 8000; override either inside `expect`. Pick the
`contains` string from the page's `<title>` or headline, something that a 404, a login
wall or a stranger's site would never print. Commit and push; the next scheduled run
picks it up. To check it now: Actions, probe, Run workflow, or `node probe.mjs` locally
(without a `GITHUB_TOKEN` it probes and writes state but touches no issues).

## Run locally

```sh
node probe.mjs          # full run, including the 30 s retry wait on failure
node probe.mjs --fast   # same, no wait (testing)
```

## Zero paid services

GitHub Actions minutes on a public repo, GitHub Issues, GitHub Pages, raw.githubusercontent
for the page's data, and ntfy.sh if you turn it on. No accounts beyond GitHub.
